# 2026-10-30 watch: `fields` says which value inside a watched result stopped, v0.10.0 published

## Summary
`watch` summarised the sampled value as one value, so a component whose `angle` froze while its `frames` counter kept counting read `changed: true, constant_since_frame: null` and named no stopped field. It now adds `fields`: one entry per leaf of the sampled value with the same four numbers, ranked stopped first. An independent review found three ways the first draft could still mislead (two in round 1, one in round 2); all three are fixed and pinned. The dev evals did not move, so the change rests on its ground-truth test, not on an eval gain. v0.10.0 (which also carries the earlier unreleased `replay` removal and anomaly fixes) is on crates.io.

## Change: `watch` per-field summary (B-094)
Plan: a new `src/server/watch_fields.rs` (`movement`, `fields`, `Movement`, `Fields`), the `watch` handler in `src/server/mcp_tools.rs` calling it for both the whole-value numbers and `fields`, the tool description, `docs/mcp-tools.md` (generated), CHANGELOG, CLAUDE.md, README.
Goal: an agent watching a composite value learns in one call which of its values stopped changing and from which frame.
Proof: `tests/fixture_ground_truth.rs::watch_without_a_pointer_says_which_spinner_field_froze` failed on 7d2e7a1 with "the reply has no `fields` array" (the report showing `changed: true, constant_since_frame: null` for a window that spanned the freeze) and passes.
Candidates considered: (1) this; (2) B-093, let `detect_anomaly` take component names, needs an eval that fails today first (the fixture has none of Velocity/Health/Alive); (3) B-021, a frame ring beside `burst`, needs per-frame GPU readback in the plugin and a rendering fixture, far past the diff cap on a loaded host.

Reply shape: `fields` is absent when the sampled value holds fewer than two leaves. Each entry: `pointer` (the request's `pointer` plus the RFC 6901 path, so it can be passed back), `changed`, `distinct_values`, `first_change_frame`, `constant_since_frame`, and `absent_samples` only when non-zero. Ranked: moved between held values and then stopped, then other changed values, then never moved; natural pointer order (`/2` before `/10`); at most 40, `fields_omitted` counts the rest. The whole-value numbers now come from the same `movement` function.

## Review
Round 1 (fresh-context `reviewer`, diff plus plan plus gate and eval output): two material gaps and three minor.
- A leaf that vanished (a despawn swap-removes a query row) read `changed: true` plus a `constant_since_frame`, which the description defined as "moved and then stopped". Survived the skeptic pass. Fixed in 84fd461: `constant_since_frame` is null for a value gone from the last sample, and `absent_samples` counts the gaps.
- The 40-entry cut ranked only changed before unchanged, in text order, so with more than 40 moving leaves a stopped one could be cut with only a total in `fields_omitted`. Survived. Fixed in 84fd461: rank stopped, moving, never moved; natural order.
- Minor: README edit uncommitted (committed in 84fd461); "pointer order" was text order (fixed with the ranking); `fields` not counted toward the 60,000-byte series cap. Dismissed: `fields` is hard-capped at 40 entries, so it is bounded and does not grow with samples x value size. The reviewer accepted this in round 2.

Round 2: one more gap. `rank` put `[missing, 3, 3]` (a spawned row) and `[5, missing, 5, 5]` in the stopped group. Survived. Fixed in 62bb197: rank 0 needs two distinct values the field actually held. Two rounds used, as allowed.
