# 2026-10-30 burst: `burst` tool, a labelled contact sheet of a short capture sequence

Focus: none (backlog B-021) · Outcome: shipped, no release (6 h rule: v0.7.2 tag ~3 h old)

## Summary
Agents could only capture single frames, so "does it move / when does it stop" needed N `screenshot` calls and
eyeballing. `burst` captures a reference plus 1-7 frames at 0.5-10 fps (default 4) and returns one contact sheet
(2x4 at most), each cell labelled with the game frame the plugin reported and the ms since the burst began.

## Change: `burst`
Plan: server-side only. `capture_once` extracted from `screenshot`; new `src/server/contact_sheet.rs` (3x5 bitmap
font, no font file); `burst` tool. Goal: a change over time visible in one image with trustworthy per-cell provenance.
Proof: `tests/agent_tools.rs::burst_labels_every_cell_with_the_frame_the_game_reported` (fake game whose frame advances
per capture: 4 distinct frames 43..73, sheet.png/ref.png/frame-n.png written, >= 300 ms elapsed at 10 fps),
`burst_refuses_out_of_range_arguments_before_capturing`, and 4 `contact_sheet` unit tests (cell placement, labels, scaling, refusals).
Candidates: B-021 ring buffer (larger, later); B-024 wrapper structs (no agent-visible effect).
Assumed decision: the reference occupies one of the 8 cells, so `frames` is 1-7 (alternative: 8 plus a separate
reference); chosen to keep the sheet at the specified 2x4. Also fixed in passing: `screenshot` turned a missing
`width`/`height` into `0x0`; now an error.
