## Summary
No bug, consumer or enhancement issue was workable (#1 stale, #2 a question), so Phase 2 took backlog B-045: agents polled `brp` dozens of times to see a value change. ## Change: watch
Plan: server-side poll; each sample is a JSON-RPC batch [`bevy_fairy/status`, method] so the frame is the one the value was read on. Files: `src/server/brp_client.rs` (`send_batch`), `src/server/mcp_tools.rs` (`WatchRequest`, `watch`), `tests/fixture_ground_truth.rs`, `docs/mcp-tools.md`.
Proof: `watch_reports_where_the_planted_spinner_bug_stops_the_angle` (angle frozen at `SPINNER_STEP*SPINNER_STOPS_AFTER_FRAMES`, freeze frame >= stop frame), `watch_stamps_every_sample_with_the_frame_it_was_read_on` (frame - spinner.frames constant), `watch_refuses_what_it_cannot_measure`. Failing-first: tests were written before the tool existed and did not compile (`WatchRequest`, `tools.watch` missing).
Candidates considered: burst capture/ring buffer (B-021, larger), delete dead modules (B-013, no eval signal).
Assumed decision: poll rather than stream `+watch`, since bevy_remote's watches only report one entity's component changes; no progress notifications (30 s cap instead).
