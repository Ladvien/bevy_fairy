## Bugs fixed
### B-083 (#14): `observe` could not name `Mesh3d`, `Camera3d`, `avian3d::*` or `Time<..>`
Must-fix: misleads **yes**, blocks **yes**, common/no workaround **yes**. Live, before: `find entities with component bevy_mesh::components::Mesh3d` answered `{"error":"Query parsing failed"}`, and the unregistered-name error told the agent to use exactly such a path.
Fix (root cause: the five query shapes captured `[a-zA-Z_:]+`): `PATH` and `PATH_LIST` classes with digits and generic arguments, and `split_component_list`, which splits only at commas outside `<>` and `()`. Commit `909161b`; the review's follow-up (`without` and `find N` refused a generic path with a space that `with` accepted) is `420019e`.
Failing-first checks: `query_parser::tests::component_paths_with_digits_parse` and `generic_component_paths_parse_and_only_top_level_commas_separate` ("Unrecognized query pattern" before); `tests/fixture_ground_truth.rs::observe_names_a_registered_component_whose_path_has_a_digit` (ground truth: the fixture registers `Mesh3d` and spawns none, so none has one and every entity lacks one; one resource holds `Time<Real>`).

### B-084 (#12): `bevy_fairy/time` speed overflow, and `held: false` when the engine clamped
Must-fix: misleads **yes**, blocks **yes** (the game panics), common no. `Time<Virtual>` multiplies the raw delta with `Duration::mul_f64` before its `max_delta` clamp (bevy_time-0.20.0 `virt.rs:250`), and the request is re-applied every frame.
Fix: `speed` in (0, 1000]; the reply gains `clamped_by_max_delta`; `held` is true when the speed in force is the request's. Commit `0dccbfa`.
Failing-first checks: `tests/plugin_clock.rs::a_speed_the_clock_cannot_represent_is_refused_not_applied` (the call returned Ok), `a_speed_the_engine_clamps_is_held_and_says_it_was_clamped` (held was false), `a_host_that_ignores_a_clamped_speed_is_still_not_held` (no `clamped_by_max_delta`); `the_largest_speed_the_command_accepts_runs` pins the bound itself.

### B-085 (#13): anomaly entity growth divided by `window_size`; `configure` never resized
Must-fix: misleads **yes**, blocks no, common/no workaround **yes**. 20 entities per sample read as 0.2 under the default window of 100.
Fix: divide by the samples spanned, report `samples_spanned`, `RingBuffer::set_capacity` from both detectors' `configure`, and no up-front `with_capacity` (a window of `usize::MAX` is a window). Commit `de9d33c`.
Failing-first checks: `anomaly_detector::tests::entity_growth_is_per_sample_spanned_not_per_window_size` (0 anomalies, wanted 1), `configure_resizes_the_window_that_growth_is_measured_over` (growth_rate 40.0, wanted 20.0), `configure_resizes_the_per_entity_velocity_histories` (history 4, wanted 2). `a_window_larger_than_memory_is_a_window_not_an_allocation` passed before the fix; it guards the lazy allocation.

### B-086 (found by the independent review of B-085): `configure` accepted a window smaller than `min_samples`
Must-fix: misleads **yes**. With the buffers really resized, `window_size: 5` under the default `min_samples` 10 is a detector that never reports, and `configure` answered success. `handle_configure` now refuses it, naming both fields. Commit `1661e39`. Checks: `tools/anomaly.rs::configure_refuses_a_window_below_min_samples` (success before), `a_window_smaller_than_the_samples_a_detector_needs_is_refused` (boundary).
