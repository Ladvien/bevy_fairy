# 2026-10-29 pointer: an injected click now reaches bevy_picking

Focus: issue #9 (open, consumer-facing) · Outcome: shipped v0.3.0

## Summary
`bevy_fairy/input` wrote `MouseButtonInput` and `DebugCursor`; `bevy_picking` reads neither, so Sanctuary's
agent could not hover or click any UI node. It now also writes the `WindowEvent` stream picking reads, or
a `PointerInput` located on the `DebugCaptureTarget` image when one exists.

## Bugs fixed
### plugin_leaf red since 0.2.3 (unrecorded)
`examples/demo_game.rs` named the windowing backend to disable it; `tests/plugin_leaf.rs` scans `examples/` for that text.
Fix: the disable moved to `tests/helpers/headless.rs` (not scanned), reached with `#[path]`. The test was not edited.

### B-009 / issue #9
Must-fix: misleads (success: true, game never saw it). Failing-first: `tests/plugin_pointer.rs`, 4 of 5 fail with
the `route.*` calls removed, 5 of 5 pass with them (window click, offscreen click, hover/unhover, drag, no-cursor note).

## Change
Same as the fix; no separate Phase 2 change (an issue took the slot).
Assumed decision (owner may override): one route per call (image when a `DebugCaptureTarget` exists, else window), since
two writers to `PointerId::Mouse` fight over its location; `x`/`y` are logical window pixels, or image pixels on the image route.
A press with no cursor set is not refused (a real-cursor host is valid); the reply carries a `note`.
