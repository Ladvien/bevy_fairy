# 2026-10-30 observe: three misleading answers fixed (diff summary, semantic phrases, ignored limit), handler on its request struct

Focus: none (priority order) · Commits: 70111e9..917874c · Outcome: shipped

## Summary
`observe` gave three kinds of wrong answer, and all three are fixed against the fixture. Its diff summary said `entities_modified: 0` beside every component change. Its semantic phrases claimed thresholds and analyses it never applied, and `find memory leaks` named the mover as a leak. `find N entities` ignored N. The Phase 2 change moves `observe::handle` onto `ObserveRequest` and deletes its unreachable snapshot history. An independent review found that a diff over a `find N` cut misreported a despawn, and that is fixed too. The gate and the evals are green, with no regression.

Baseline: e9a75f9 changed no code since fa6a556, whose gate (ratchet OK) and dev evals (6/6, 5.3 calls, 1 invalid) are the baseline. This pass did not re-run them.

## Bugs fixed
### B-078: diff summary said `entities_modified: 0` beside every component change
- Must-fix: misleads **yes**, blocks no, common/no workaround no.
- Evidence (live, previous pass): `components_modified: 1, entities_modified: 0` for the moving mover.
- Root cause: `DiffSummary::from_changes` counted only `ChangeType::EntityModified`, and `diff_snapshots` never produces it.
- Fix: count the distinct entities with a component that was added, removed or modified. Commit 70111e9.
- Failing-first check (ground truth): `fixture_ground_truth::observe_diff_reports_the_mover_moving_between_two_reads` now asserts the summary. Before the fix it got `left: 0, right: 1`; it passes after.

### B-077: semantic phrases claimed selections the server never made
- Must-fix: misleads **yes**. `query_params` never sends `where_clause`. Against the fixture, `find memory leaks` returned the mover (its one entity with a `Transform`) as a leak candidate at "confidence" 0.6.
- Fix: the phrases are refused as unrecognised queries and the refusal lists the shapes that work. Commit f49baf1. These are removed:
  - `QueryParser::parse_semantic`;
  - the semantic attempt inside `parse`;
  - the `semantic_analysis` and `metadata.resolved_component_names` fields;
  - the short-name rewrite;
  - the two schema examples.
- Assumed decision (owner may override): of (a) evaluating the thresholds server-side, (b) refusing only the threshold phrases, and (c) removing all of them, I picked (c).
  - The thresholds target a `Velocity { linear: {x, y} }` that no Bevy or physics-crate type has.
  - The "magnitude" claim is checked per axis.
  - The phrases without thresholds mislead as well.
  - Removing them is reversible and is the smallest honest change.
- Failing-first check (ground truth): `fixture_ground_truth::observe_refuses_the_semantic_phrases_it_never_evaluated`.

### B-079: `find N entities with component Y` ignored N
- Must-fix: misleads **yes** (ignored argument). Found in this pass's honesty audit: the parser bound the limit to `_limit`.
- Fix: `QueryParser::parse` returns `ParsedQuery { request, limit }`. `observe` cuts the rows and reports `metadata.limit` and `metadata.matched`, and refuses `find 0`. Commit 1032672.
- The parser's help text is now built from the pattern descriptions. It used to be a hand-kept copy, and the descriptions were never read (a `dead_code` warning).
- Review round 1 found a gap, fixed in 917874c. The cut ran before the diff snapshot. A despawn moves the last table row into the freed slot, so a crate that had existed all along was reported as `EntityAdded`. Now the diff runs on every match, the cut applies only to `result`, and `diff.compares` says so.
- Failing-first checks (ground truth):
  - `fixture_ground_truth::observe_find_n_entities_returns_n_and_says_how_many_matched` returned 6 rows for `find 2` before the fix.
  - `fixture_ground_truth::observe_diff_with_a_limit_reports_only_what_the_game_changed` gave `entities_added` 1 with the fix stashed. It passes with it.
